════════════════════════════════════════════════════════════
КОНТЕКСТ ПРОДУКТА
════════════════════════════════════════════════════════════

Это НЕ swipe-based dating app.
Это психологическая платформа для поиска long-term совместимости.

Система анализирует:
- attachment style пользователя
- emotional regulation паттерны
- жизненные ценности
- стиль конфликта
- нервную систему (stress reactivity)
- коммуникационные паттерны
- long-term goals

Matching происходит через 6-слойный compatibility framework,
а не через внешность или поверхностные интересы.

model User {
  id                String    @id @default(cuid())
  email             String    @unique
  name              String?
  avatarUrl         String?
  createdAt         DateTime  @default(now())
  deletedAt         DateTime?
  onboardingDone    Boolean   @default(false)
  onboardingStep    Int       @default(0)

  profile           Profile?
  behavioralEvents  BehavioralEvent[]
  matchesAsA        Match[]   @relation("MatchUserA")
  matchesAsB        Match[]   @relation("MatchUserB")
  sentMessages      Message[]
  accounts          Account[]
  sessions          Session[]
}

model Profile {
  id                    String    @id @default(cuid())
  userId                String    @unique
  user                  User      @relation(fields: [userId], references: [id])

  // Personality vector (128-dim, хранится как float array)
  personalityVector     Float[]

  // Attachment style scores (сумма = 1.0)
  attachmentSecure      Float     @default(0)
  attachmentAnxious     Float     @default(0)
  attachmentAvoidant    Float     @default(0)
  attachmentDisorganized Float    @default(0)

  // Values map (12 dimensions, each 0-1)
  valuesAutonomy        Float     @default(0)
  valuesSecurity        Float     @default(0)
  valuesAchievement     Float     @default(0)
  valuesBenevolence     Float     @default(0)
  valuesConformity      Float     @default(0)
  valuesTradition       Float     @default(0)
  valuesPower           Float     @default(0)
  valuesStimulation     Float     @default(0)
  valuesHedonism        Float     @default(0)
  valuesUniversalism    Float     @default(0)
  valuesSelfDirection   Float     @default(0)
  valuesSpirit          Float     @default(0)

  // Conflict style
  conflictCompete       Float     @default(0)
  conflictAvoid         Float     @default(0)
  conflictAccommodate   Float     @default(0)
  conflictCollaborate   Float     @default(0)

  // Nervous system
  nervousActivation     Float     @default(0)
  nervousDeactivation   Float     @default(0)
  nervousWindowTolerance Float    @default(0)

  // Emotional regulation
  emotionFlooding       Float     @default(0)
  emotionRumination     Float     @default(0)
  emotionRepair         Float     @default(0)
  emotionSuppression    Float     @default(0)
  emotionExpression     Float     @default(0)

  // Growth
  growthFixed           Float     @default(0)
  growthOriented        Float     @default(0)

  // Communication
  commDirect            Float     @default(0)
  commIndirect          Float     @default(0)
  commAssertive         Float     @default(0)
  commPassive           Float     @default(0)

  // Confidence scores per dimension
  confidenceScores      Json      @default("{}")

  // AI-generated insights (хранить как JSON)
  personalityInsights   Json?
  rawOnboardingData     Json?

  lastInferredAt        DateTime?
  updatedAt             DateTime  @updatedAt
}

model BehavioralEvent {
  id          String    @id @default(cuid())
  userId      String
  user        User      @relation(fields: [userId], references: [id])
  eventType   String    // 'onboarding_choice', 'message_sent', 'match_viewed', etc.
  sessionNum  Int?
  questionId  String?
  choiceValue Json      // НЕ raw text — только metadata
  timingMs    Int?      // время ответа в миллисекундах
  createdAt   DateTime  @default(now())
}

model Match {
  id          String    @id @default(cuid())
  userA       User      @relation("MatchUserA", fields: [userAId], references: [id])
  userAId     String
  userB       User      @relation("MatchUserB", fields: [userBId], references: [id])
  userBId     String

  // Compatibility breakdown
  layerScores           Json      // {nervous: 0.8, attachment: 0.6, values: 0.9, ...}
  overallScore          Float
  chemistryScore        Float
  stabilityScore        Float
  tensionPoints         Json?     // predicted conflict areas
  resonancePoints       Json?     // predicted connection areas
  confidenceScore       Float     @default(0)

  // Status
  outcome               String?   // null | 'connected' | 'declined' | 'ghosted' | 'relationship'
  shownToA              Boolean   @default(false)
  shownToB              Boolean   @default(false)
  shownAt               DateTime?

  messages              Message[]
  computedAt            DateTime  @default(now())

  @@unique([userAId, userBId])
}

model Message {
  id          String    @id @default(cuid())
  matchId     String
  match       Match     @relation(fields: [matchId], references: [id])
  senderId    String
  sender      User      @relation(fields: [senderId], references: [id])
  content     String    // в реальности — E2E encrypted
  messageType String    @default("user") // 'user' | 'ai_suggestion' | 'system'
  metadata    Json?     // для AI сообщений — какой prompt использовался
  createdAt   DateTime  @default(now())
  readAt      DateTime?
}

lib/matching/engine.ts

Реализуй MatchingEngine класс со следующей логикой:

async findMatches(userId: string): Promise<Match[]>

Алгоритм:
1. Загрузи профиль пользователя из БД
2. Vector similarity search через pgvector:
   SELECT * FROM profiles
   ORDER BY personality_vector <=> $1
   LIMIT 200
   (реализуй через Prisma $queryRaw)
3. Прогони через ConflictDetector — отфильтруй hard incompatibilities
4. Для топ-50 запусти aiService.computeCompatibility()
5. Примени chemistry boost для complementary patterns
6. Примени uncertainty dampening для неполных профилей
7. Верни топ-7 с полным breakdown

lib/matching/conflict-detector.ts

Реализуй ConflictDetector.detect(profileA, profileB):
Возвращает { hasHardConflict: boolean, conflicts: ConflictData[] }

Hard conflicts (фильтровать полностью):
- Оба имеют extreme avoidant > 0.8 (взаимное избегание)
- Values polar opposites на критических dimensions (diff > 0.85)

Soft conflicts (передавать в tensionPoints):
- anxious + avoidant pattern
- Opposite conflict styles (compete + accommodate)
- Разные growth orientations

- Возвращает первые insights

/api/matches
GET
- Возвращает матчи пользователя с compatibility data
- Lazy-load personality inference если ещё не готова

/api/matches/[id]
GET
- Полный compatibility breakdown
- TensionPoints и ResonancePoints
- Narrative summaries

/api/chat/[matchId]/ai-suggestion

POST { userId }
- Запускает personality inference вручную
- Только в development

════════════════════════════════════════════════════════════
КРИТИЧЕСКИЕ ТРЕБОВАНИЯ
════════════════════════════════════════════════════════════

1. TypeScript strict mode везде. Никаких any.

2. Все AI вызовы ТОЛЬКО через aiService из lib/ai/index.ts.
   Никаких прямых вызовов в компонентах или API routes.

3. Personality data и PII хранятся в разных таблицах.
   Profile не содержит email/name. User не содержит psychological data.

4. Система никогда не показывает пользователю:
   - Единый процент совместимости
   - Personality type labels ("ты — INTJ")
   - Клинические термины (attachment disorder, etc.)
   Только паттерны и тенденции с uncertainty.

5. Onboarding questions должны быть РЕАЛЬНЫМИ —
   не placeholder типа "Question 1". Психологически продуманными.

6. AI стабы должны возвращать разные значения для разных inputs
   (детерминированный hash от userId, не полный random).
   Это важно для тестирования UI.

7. Весь matching алгоритм должен быть полностью работоспособен
   на stub данных — конец-в-конец от onboarding до chat.

8. Никакой зависимости от внешних AI API в runtime.
   Проект должен полностью работать с AI_USE_STUBS=true.

Начни с создания структуры проекта и установки зависимостей.
